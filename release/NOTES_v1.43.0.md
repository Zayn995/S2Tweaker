# S2Tweaker 1.43.0 — control compatibility and optional extended damage mercy

NPC Search Time and Alertness previously copied the complete indexed NPC profile,
including each other's unchanged values. They now write only their own changed
fields. The same correction has been applied across other affected controls.
Thanks to **craigduk76** for the config comparison that exposed the problem in
[issue #13](https://github.com/Zayn995/S2Tweaker/issues/13).

## Corrected patch output

- NPC search/alertness, flashlight brightness/reach and cone width.
- Radiation dose, screen filter and Geiger intensity; jam chance and clearing time.
- Scope zoom and handling references; wounded/dead encounter fractions.
- Rain/emission frequency, weather duration/transitions and weather sense details.
- Hearing, crouch/movement/surface noise; squads, expansion and camp activities.
- Map markers, landing/limp thresholds, grenade resistance, sprint stamina and repair modifiers.
- Effect caps and carry thresholds, with caps and indices read from installed data.
- Artifact cache weights and additional bonus slots; existing bonuses and required
  fake/quest inheritance shields remain intact.
- Repeatable-job conditions and connections; trader restriction additions.

Existing nodes receive only changed fields. New effect, equipment and quest nodes
retain their required definitions. Numeric no-ops are omitted, and cancelling an
individual/global change no longer removes unrelated sibling changes.

## Optional extended damage mercy

**Allow damage-mercy weights above 1.0 (experimental)** removes the tool's cap when
explicitly enabled. At 300%, a live weight of 1.0 becomes 3.0. Inherited difficulty
values are resolved as well. Existing presets retain the default cap; at 100% the
checkbox alone produces no patch. See [issue #20](https://github.com/Zayn995/S2Tweaker/issues/20).

These are curve weights, not percentages of protection. Engine behavior above 1.0
is unconfirmed and may clamp or behave unexpectedly. The option starts off.

## Updating

Extract the complete `S2Tweaker_v1.43.0.zip` and keep all runtime files together.
Preserve your settings, editor state and presets when moving folders.

**Rebuild affected Paks**, including both sides of previously conflicting exports.
Paks generated by 1.42.0 and earlier keep their old full-profile assignments.
Give separate exports different names **inside the tool**; renaming only the Pak
does not change its internal patch filenames. Replace superseded Paks and scan
your installed mods again.

Related controls that deliberately modify the same field should be configured
together in one export. Competing artifact additions can also use the same new
slot. This update does not make all combinations of separate mods compatible.

## Verification and limits

60 local headless suites and a 5,652-case setting-output audit passed. Regression
coverage includes independent patch orders, installed baselines, numeric no-ops,
inheritance, combined exports and Pak write/read checks.

**The new patch output and extended mercy mode have not been play-tested.** Local
merge checks implement the documented config contract; they do not execute the
game parser. NPC reactions/searches, weather transitions and extended mercy still
need in-game comparisons. [Detailed evidence and limits](https://github.com/Zayn995/S2Tweaker/blob/v1.43.0/docs/NPC_PATCH_COMPATIBILITY.md).

No animation changes, UE4SS or Zone Kit dependency. All 19 native runtime binaries,
including the signed Python starter, remain byte-identical to 1.42.0. The
application source changes, so this ZIP has a new hash. No new VirusTotal result
is claimed. `S2Tweaker_v1.43.0_source.zip` contains the matching public source.

The Windows build workflow runs `tools/public_files.py`, `tests/run_ci.py`, refreshes
the pinned portable runtime with `tools/refresh_portable.py`, and checks the
portable self-test plus binary hashes and signatures.
