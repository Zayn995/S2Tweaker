--- Changelog ----------------------------------------------------
1.34.0 - the several-jobs switch actually works now

- 'Accept several jobs in one conversation' is repaired. Molkerr play-tested
  1.33.0 and reported that it did nothing. Taking a task giver's quest apart
  node by node showed two mistakes: accepting a job does not merely end the
  conversation, it switches the dialogue node OFF (the accept node hangs on
  it as an excluding launcher), and the extra launcher the tool added carried
  a merge flag although it was a brand-new entry. Both fixed.
- Handing one job in no longer has to take the others down with it. The
  giver's round-end node shuts down everything inside his quest, including
  the jobs you still carry; with the switch on, that one key is off. 634 of
  the game's 1395 end nodes already ship that way. Still untested and the
  riskiest thing here - please report back.
- Nothing else changed: no new sliders, no new game files, existing paks and
  presets stay valid.

1.33.0 - ten dials from other people's mods, and the first play-test acted on

- Someone finally tested this in the game. Molkerr played 1.31.0 and sent
  four findings; two were real bugs here. Ammo stack sizes are confirmed
  working in-game - the first hard confirmation this tool has ever had.
- 'Accept several jobs in one conversation' (Economy): the counter raised
  in 1.31.0 only decides how many jobs a giver PREPARES per round, and his
  dialog closed after one yes. A new switch re-opens it a second after you
  accept. It stores nothing in your save and clears none of the game's own
  bookkeeping, so pulling the pak out leaves no trace.
- Edition (DLC) items follow the item sliders now. The 22 Deluxe /
  Pre-Order / Ultimate items declare their own grid size, weight, use time
  and durability; the general item sliders had never reached them.
- 'Anomaly wear on gear': one slider for the whole corrosion family - an
  anomaly hit costs armour, helmet and both weapons 0.2 to 25 points of
  condition. 0 % stops it entirely.
- 'Weapon & armor max condition': how much condition there is to begin
  with. Condition lives in your save, so it shows on gear that spawns
  after you install the mod.
- 'Damage at extreme range': past the drop-off distance a shot keeps only
  10 to 60 % of its damage. This is the floor under that.
- A-Life: lair starting occupancy, how often rarer archetypes appear, how
  fast lairs expand toward you, the director's fallback spawn count.
- Ammunition: two more per-round factors (spread, spread while aiming).
- 'Stamina & bleeding caps': the two ceilings in the effect table nothing
  else here touched.
- Inventory stat bars now move accuracy and handling too, as an honest
  approximation (accuracy follows spread, handling follows aim time).
- Correction: the 'artifact visibility radius' slider from 1.28.0 sits on
  a key whose meaning could not be proven. The mod it was modelled on
  changes the DETECTOR's display radius instead - which 'Detector &
  scanner range' has done all along. Renamed, and it says so.
- Upgrade strength now also covers the accuracy and movement-speed upgrade
  effects, which hung on no slider at all.
- No new game files are read: no re-extraction, paks and presets stay
  valid. Nothing else play-tested - please report back.

1.31.0 - More repeatable jobs, and eight dials from other people's mods

- 'Repeatable jobs per round' (Economy), requested on GitHub. Measured
  first: each of the eight task givers hands out THREE jobs and then goes
  quiet until a 24-hour timer resets his counter - which is never counted
  back down when you hand a job in. The slider raises the three, capped
  per giver at the number of different jobs he actually has (6 to 10).
- 'Task givers offer the next job right away' (switch under it): vanilla
  only reopens the job dialogue once a giver has run dry, which is why
  you leave with one job per visit. This lets him offer the next one
  while he is below the limit - that is what lets you carry several at
  once. Works together with the existing cooldown slider: how many per
  round, and how often a round starts.
- Four more per-round modifiers (Ammo tab and in the tree): bleeding,
  recoil, trajectory flatness, and how hard a round is on the barrel.
- 'Ammo pack size': how many rounds a picked-up pack holds (vanilla 30
  for rifle rounds, 10 to 50 for the rest). Launcher grenades stay at 1.
- 'Weapon jam chance': vanilla gives each gun its own (4.5 to 15);
  0 % = no weapon ever jams. The condition at which it starts is kept.
- 'Inventory stat bars follow your changes' (switch, Weapons): those
  bars are hand-set numbers the game never recomputes - that is why they
  never moved. Now damage, range and fire rate follow your sliders.
  Accuracy and handling stay put; they are mixed values. Cosmetic only.
- 'NPC vs NPC damage': stalkers hit each other for 70 % of normal damage
  in vanilla, which is why faction fights drag on.
- 'Mutant attacks per series' and 'Mutant bleeding buildup'. Human and
  boss attacks carry the same keys and are left vanilla on purpose.
- 'Repair surcharge per upgrade' (Economy): every fitted part adds 0.2
  to the repair bill in vanilla. 0 = upgrades are free to maintain.
- 'Stash item variety' (World): how many different item groups a stash

- No new game files are read: no re-extraction, paks and presets stay
  valid. Nothing here is play-tested in-game - please report back.

1.30.0 - Bigger inventory stacks

- Requested on GitHub. Measured first: the game caps AMMUNITION at 900

  PDAs/notes/keys at 300000, and binoculars, detectors, the weird DLC
  artifacts and money cards at 1 on purpose. That last group is never
  touched.
- 'Ammo stack size' (Ammo tab): x 10 turns 900 into 9000. The same value
  PER ROUND as the fifth factor in the ammo tree - a round's own factor
  beats the global slider.
- 'Food & medicine stack size' (Weight & items) for the 22 consumables
  that sit at 999.
- Whole numbers, never below 1, capped at 300000 - the value the game
  itself uses for 'unlimited'.
- Pairs with 'Max carry weight' and 'Item weight': in vanilla the weight
  stops you long before the stack does (900 rounds of 7.62 weigh 21.6 kg
  of your 80), so the stack cap only becomes the real one once you raise
  carrying capacity - or in a stash, where weight does not count.
- No new game files are read: no re-extraction, paks and presets stay

1.23.0 - no more repak.exe: pak files are handled by plain Python

- The folder no longer contains repak.exe (the open-source pak tool
  earlier versions bundled). Its job is done by the tool's own Python
  code now; nothing else changes in the tool.
- Why: repak.exe was the only unsigned executable in the package, and
  Microsoft's machine-learning engine flagged two builds of it (same
  source, 27 bytes of linker timestamp apart) as a trojan. Now there is
  no unsigned executable at all: S2Tweaker.exe is the signed python.org
  interpreter, every DLL is signed by the PSF or Microsoft.
- Verified against the real game: the 36 needed game files come out
  byte for byte as repak extracted them, 27 third-party mod paks read
  identically, and the paks written have the same index, entries and
  checksums as repak's.
- Oodle stays a manual step, exactly as before: not shipped, not
  downloaded; put oo2core_9_win64.dll next to S2Tweaker.exe once.
- A leftover _internal\repak.exe from an earlier version is removed on
  the first start.
- Not play-tested, like the rest of the tool. Existing paks stay valid.

1.21.0 - no more PyInstaller: the launcher is the signed python.org
interpreter

- Nothing changes in the tool itself. What changes is the download:
  S2Tweaker.exe is now pythonw.exe from python.org, byte for byte,
  digitally signed by the Python Software Foundation. That is why the
  exe shows the Python icon and Python's version info - changing either
  would break the signature. The tool's version is in the window title.
- The tool's own code ships as readable .py files in _internal, next
  to the Python runtime and Tcl/Tk from the same python.org install.
  Every DLL, PYD and EXE in the folder is signed by the PSF or
  Microsoft, except repak.exe (open source, compiled from source by the
  public build workflow).
- No networking capability at all: Python's socket and ssl modules and
  the OpenSSL libraries are not in the package. Since 1.19.2 the program
  has had no networking code; now the runtime could not connect either.
- Why: 1.20.0 was still flagged by two engines although its launcher
  was byte for byte PyInstaller's official one, which scans clean on
  its own. The detections were aimed at PyInstaller itself, so it is
  gone. Result: 0 detections for the ZIP, the exe and repak.exe (links
  at the top of the description).
- Keep the files together: next to S2Tweaker.exe there are now
  python312.dll, vcruntime140.dll and python312._pth as well as the
  _internal folder. To update, extract the ZIP over your S2Tweaker
  folder; settings, presets, cache and output are not in the ZIP and
  stay untouched.
- No new game files, no re-extraction. Your existing paks stay valid.

1.20.0 - change which ammunition a weapon uses

- New: an "Ammunition" dropdown per weapon (Weapons tab, "Single weapon
  overrides", above the sliders). Requested on GitHub by Molkerr. Every
  caliber the game actually uses is offered.
- It does NOT change damage. Damage comes from the weapon - that is the
  Damage slider; the round only adds a multiplier, and that multiplier
  is the same for every rifle and pistol caliber. A swap changes
  penetration, bullet flight, price and how easy the ammo is to find.
- It changes NPC weapons too: the caliber lives on the weapon setup that
  player, NPC and boss versions share. The tool tells you how many item
  variants share the one you are about to change.
- Nothing is blocked, not even broken combinations. A rifle on shotgun
  shells drops to about 8 % of its damage; a shotgun on rifle rounds
  jumps to roughly 12x. The tool computes those numbers from your own
  game files, shows them, and then lets you do it.
- 7.62x39 is missing on purpose: no weapon uses it and it drops from no
  loot generator, so a weapon switched to it would never find ammo.
- No new game files, no re-extraction. Your existing paks stay valid.

1.19.2 - no network code, and no archive hidden inside the exe

- The executable was 90% compressed archive. Shipping as a folder in
  1.19.0 only moved the DLLs out; the Python code stayed inside
  S2Tweaker.exe as a 2,857,284-byte compressed blob with an entropy of
  7.999 out of 8.0. A small loader in front of a large opaque block is
  what a packer looks like, and it is how analysts recognise malware
  built with the same tooling. The code now ships as ordinary files
  beside the exe: the program file is 345 KB instead of 3.2 MB, and one
  of the three scanners that flagged it stopped.
- The update check is gone, and with it every trace of networking - no
  urllib, no sockets, no HTTP client. Nexus' own file guidelines
  prohibit executables that connect to the internet "unless where it is
  crucial" and state that "'auto update' functionality does not qualify
  as crucial". They are right, so it is out. You can verify that with
  one search of the public source.
- To update from now on: download the new ZIP and replace S2Tweaker.exe
  and the _internal folder next to it. Settings, presets, cache and
  built mods are never touched. The version is in the window title.
- This download is the build server's own output, taken from the public
  GitHub Actions run and uploaded unchanged. Nothing in it was built on
  a private machine.
- No new game files, no re-extraction. Your existing paks stay valid.

1.19.1 - nothing is downloaded while the tool runs

- The tool no longer fetches anything at runtime. It used to download the
  Oodle decompression library on first use and load it, which is exactly
  what a dropper does and one reason scanners flagged it. That code is
  gone. A setup window now walks you through placing that file once, with
  pictures, and shows where it goes. It only appears when the file is
  missing, and an indicator in the header shows the state at a glance.
- The pak tool it bundles (repak) is built from source with its download
  function and whole HTTP/TLS stack removed, so it cannot fetch anything
  either. It is no longer a third-party prebuilt binary.
- Sorry about the one manual step. The library may not be shipped, cannot
  be taken out of the game (it is compiled into the game executable), and
  the open re-implementations have no licence. Doing it automatically was
  the old answer, and that is what got this tool flagged.
