# Optional loot extensions — implementation design

This builds on `STASH_VARIETY_RESEARCH.md` and `LOOT_MODS_RESEARCH.md` using the current extracted originals. No foreign configuration lists are shipped.

Extra stash finds are attached to individual spawn instances, rather than the four shared GamePass pools. Only containers which spawn on the main `WorldMap_WP`, have no edition requirement, and already use a safe ordinary stash generator reaching one of those pools qualify. Generator inheritance uses the closest explicit ItemGenerator block; inherited arrays are not blindly unioned. Quest sublevels, unsafe direct or nested rewards, missing references and cycles are rejected. Existing spawn rank entries and their generator assignments stay in place; a uniquely named sibling adds a new helper generator.

Each category uses the existing native SubItemGenerator/Chance schema and a separate Weight lottery. Stash weapons and armor derive from current ordinary NPC rank pools; attachments derive from ordinary safe loot, and artifacts must appear in live artifact spawners and exclude archiartifacts. All items are checked for current existence, visibility, quest flags, currency effects and named-unique weapons. A configured Chance is a native generation field, not a measured overall stash probability.

NPC options target ordinary named `GeneralNPC_` equipment pools after existing safety filters. Armor loot uses a separate inventory lottery of usable armor from the same faction/role and rank group. It does not claim to return exactly the NPC's equipped outfit. Lower-rank equipment diversity only adds candidates from earlier ranks of the same generator and category, respecting difficulty restrictions. Existing equipment rows remain intact. Helmet controls scale explicit Head Chance fields; guaranteed Weight-only helmet lotteries are not converted into a different selection mechanism.

Loaded ammunition changes only existing AmmoMinCount/AmmoMaxCount, preserving ordered bounds. Per-species trophy factors compose with the existing global trophy chance and ordinary quantity factors, and only affect verified ordinary MutantLoot items. The two quest flags, currency, unique-item, unknown-item and collar exclusions also apply. Array positions still come from current originals; third-party mods which reorder existing positions require effective-data compatibility support and cannot be made universally compatible by adding bpatch headers.

All new helpers and sibling entries use names prefixed `S2Tweaker_Loot_`, followed by the sanitized mod name and a digest of its original spelling. Thus two different profile names remain distinct even when sanitization produces the same readable name. New selection groups and item rows use this namespace too. Existing structures merge through bpatch; newly introduced structures are emitted as new nodes.

The first enabled stash build streams the spawn file one top-level node at a time, then keeps only vetted `(spawn SID, rank key, rank)` tuples in the GameData instance. Candidate item sets and current weapon conditions are also cached there. These caches do not depend on settings or the output mod name. Reloading game data creates a fresh GameData and fresh analyses. Default settings produce no patches and do not load the large spawn file. SpawnActorPrototypes is a new required source and therefore requires a cache schema increment.

Count scaling preserves absent fields and explicit zeros, rounds both existing bounds together, and rejects malformed, negative, reversed or non-finite source ranges. User-selected armor-condition bounds are sorted if entered in reverse. Equipment diversity does not transfer a difficulty-limited source pool into an unrestricted target, nor move candidates across generator identities. The existing weapon-condition option only transforms newly added weapons, and the quality multiplier reweights the final expanded lottery using current item prices. Static generation and serialization can verify targeting and preservation, but do not establish runtime loot distributions or whether already-generated inventories refresh.
