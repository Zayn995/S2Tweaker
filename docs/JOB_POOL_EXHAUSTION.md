# Repeatable-job pool exhaustion

Introduced in 1.46.2. Experimental; not play-tested yet.

## Report and verified cause

[Molkerr's 17 September follow-up](https://github.com/Zayn995/S2Tweaker/issues/9#issuecomment-5718007870)
reports Hera's missing job offer returning when **Repeatable jobs per round**
is reset to vanilla 3. His attached Pak was generated by **1.45.0** on
16 September and requests five choices, zero cooldown and multiple active jobs.

The native counter increments when a job is **added to the menu**, not when it
is accepted. The native graph draws random candidates until that counter reaches
the target. The original generator only raised the target, capped by the number
of defined job containers. That total is not the current eligible pool.

In the installed data, Hera has nine definitions, but:

- `DAF_QuestSwitch_SQ04_RSQ07 = true` excludes C02, C03 and C04.
- C06, C07 and C08 exclude each other from the same menu.
- The previous-job checks and C09 completion gate can reduce the pool further.

After that story switch, at most four choices remain; some states allow only
three or fewer. A target of five can therefore leave selection repeating without
enabling the offer dialogue. This is a verified graph defect consistent with the
report. The player's save variables have not been inspected; a connection to the
Cost of Hope story sequence itself has not been established.

## Repair

For targets above a giver's native limit, the generator adds a sequence of native
If nodes before random selection. Each copies one candidate's complete live
eligibility condition tree. If any candidate is eligible, random selection
continues. If every candidate is ineligible, a positive menu counter enables the
existing offer dialog with the choices already collected. A zero counter does
not create an empty offer.

The original limit still stops a complete pool. Story/previous-job checks,
mutual exclusions, random weights, rewards, journals and counter writes remain
unchanged. This applies to all eight discovered givers, separately from the
multi-job option. Default settings emit nothing; lower limits do not need the
extra guard. Unrecognized graph layouts fail export rather than dropping gates.

The GUI treats the requested number as a maximum. Rebuild the existing Pak to
apply the repair. Keep the same multi-job option and journals for active jobs;
this change does not reset or migrate saved quests.

## Validation boundary

The live-data check preserves all 69 original eligibility condition trees.
Synthetic routing tests cover available, exhausted and empty pools, story gates,
mutual exclusions, nonstandard connection indices and preservation of existing
launchers. These checks do not simulate the full quest engine or prove recovery
of every already-saved node state.

Player follow-up should check Hera with the same save and five requested choices,
the returned menu, acceptance/hand-in and save/load. If an existing saved round
does not resume, report that state; do not force a story reset. The confirmed
workaround for released builds through 1.46.1 is to restore this one setting to
3 and rebuild, preserving the multi-job option and other quest settings.
